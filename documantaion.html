📧 MailBot – Domain Subscription Manager

MailBot is a full‑stack web application that helps businesses track domain and service subscriptions, automatically send personalised email reminders, and generate professional email templates using AI. It replaces manual spreadsheets and expensive SaaS tools, offering a self‑hosted, zero‑cost solution.

Perfect for web hosting companies, domain registrars, IT agencies, freelancers, and anyone who wants to stay on top of renewals.

📊 Old MailBot vs New MailBot – What changed?

The original MailBot (as found on GitHub) was a basic subscription tracker. We transformed it into a production‑ready system with AI, dynamic SMTP, multi‑recipient support, and a polished dashboard. The table below highlights every major change.

✨ All Key Features Explained
  • ✅
    AI Template Generator: The star feature. Instead of manually writing HTML, you type a natural language prompt like "Send a friendly reminder 7 days before domain expiry with a special discount". The AI (Gemini, or any compatible model) returns a structured JSON object containing the template name, subject, HTML body, plain text body, and the correct reminder type (e.g., reminder_7). The output is immediately pre‑filled in the creation form, ready to save.
  • ✅
    Email Verification at Registration: When a new user signs up, a random verification token is generated and a link is emailed. The account remains inactive (isVerified: false) until the link is clicked. This prevents spam accounts and ensures only valid email addresses are used.
  • ✅
    Multiple Recipients per Subscription: Each subscription can have several client emails. The form lets you add extra email fields on the fly. The first valid email becomes ownerEmail (primary) for test sends and cron reminders, while all emails are stored in ownerEmails array for future bulk sending.
  • ✅
    Subscription Categories: Two new dropdowns help organise your portfolio: Subscription Type (Domain, Hosting, SSL, Custom) and Renewal Cycle (Monthly, Quarterly, Yearly, Custom). These are stored in the database and used in the dashboard charts.
  • ✅
    Dynamic SMTP Configuration: You can save your own email server settings (host, port, username, password, sender name/email) directly from the UI. These settings are stored in the smtpsettings collection. When sending a test email or manual cron trigger, the system first checks for saved settings; if none exist, it falls back to the environment variables (.env). This means you can change email providers without touching server files.
  • ✅
    Interactive Dashboard: Powered by Recharts, the dashboard includes:
    • Upcoming Expiries – a bar chart showing domain counts per month for the next 6 months.
    • By Subscription Type – a donut chart showing the distribution across Domain, Hosting, SSL, Custom.
    • By Renewal Cycle – a horizontal bar chart.
    • Status Distribution – a simple list showing Active, Expiring Soon, Expired counts.
    • Recent Subscriptions – a list of domains expiring soon with days left and a "View All" link.
  • ✅
    Prompt Ideas Library: The "💡 Ideas" button opens a modal with 12 pre‑written prompts like "30‑day reminder", "Expired notice", "Black Friday promo". Each card has a copy button and a Sparkle button that fills the AI prompt box and opens the generator instantly – ideal for non‑technical users who don't want to type.
  • ✅
    Manual Cron Trigger: The daily cron job runs at 8:00 AM UTC. However, an admin can manually trigger the same process from the Settings page by clicking "Run Reminder Check Now". This is useful for testing or for sending reminders outside the normal schedule.
  • ✅
    Test Emails from Subscriptions Table: Next to each subscription row, a paper plane icon sends a test reminder email to the primary owner email. The backend dynamically creates a Nodemailer transporter using your saved SMTP settings (or .env fallback) and fires off a test message.
  • ✅
    Dark Mode & Responsive Design: Built with Tailwind CSS, the entire interface supports dark mode and adapts from mobile to large desktop screens.
🛠️ Tools & Libraries – Why we chose them

Frontend

  • React (Vite): Fast development and optimal builds. Vite provides hot module replacement and quick startup.
  • Tailwind CSS: Utility‑first CSS framework for rapid, responsive UI with dark mode support.
  • Lucide React: Clean icon set (Sparkles, Lightbulb, etc.) used throughout the app.
  • Recharts: Composable charting library built on D3. Used for dashboard charts – easy to customise and responsive.
  • React Router DOM: Client‑side routing for pages (Dashboard, Subscriptions, Templates, Settings, etc.).
  • React Hot Toast: Lightweight, animated toast notifications for success/error feedback.
  • date‑fns: Modern date utility library for formatting expiry dates and calculating days left.
  • Axios: Promise‑based HTTP client for API calls with automatic token injection.

Backend

  • Node.js + Express: Minimalist server framework, easy routing and middleware.
  • Mongoose: MongoDB ODM for schema definitions, validation, and query building.
  • jsonwebtoken: JWT generation and verification for secure authentication.
  • bcryptjs: Password hashing with salt (12 rounds).
  • Nodemailer: SMTP client for sending all emails – verification, reminders, tests. Supports custom transporters.
  • node‑cron: Scheduler for running the daily reminder check at 8:00 AM UTC.
  • express‑validator: Request body validation middleware.
  • crypto (built‑in): Random token generation for email verification.

AI / External APIs

  • @google/generative‑ai: Official Gemini SDK for AI template generation.
  • groq‑sdk (optional): Alternative AI provider (Llama 3).
  • openai (optional): OpenAI GPT models.
  • axios is also used to call Mistral or other custom endpoints if needed.

Database & Dev Tools

  • MongoDB: NoSQL database for flexible document storage. Can be used locally or with MongoDB Atlas (free tier).
  • VS Code: Code editor.
  • Postman: API testing during development.
  • Git & GitHub: Version control and collaboration.

⚡ Step‑by‑Step Data Flow

🔐 User Registration & Verification

  1. User fills the register form → POST /api/auth/register (auth.js).
  2. Backend creates a user with isVerified: false and a random crypto token.
  3. sendVerificationEmail(to, token) (emailService.js) sends an email with a link containing ?token=xxx.
  4. User clicks the link → VerifyEmail.jsx loads and calls GET /api/auth/verify-email?token=xxx.
  5. Backend marks user as verified, clears the token, returns a JWT.
  6. Frontend stores the JWT and redirects to dashboard.

📧 Adding Subscription & Sending Test Email

  1. User fills SubscriptionForm (multiple emails, type, cycle, intervals) and submits.
  2. Frontend sends POST /api/subscriptions with payload.
  3. Route (subscriptions.js) validates input, creates Subscription document. The pre‑save hook auto‑sets status.
  4. To test, user clicks the send icon → POST /api/subscriptions/:id/send-test.
  5. Backend loads SmtpSettings for the user (or .env fallback), creates a dynamic Nodemailer transporter, sends to ownerEmail.
  6. Result is returned to frontend; a toast shows success/failure.

⏰ Automatic Cron Reminder

  1. node‑cron (scheduler.js) fires processReminders() every day at 8:00 AM UTC.
  2. The function queries Subscription where notificationsEnabled: true and expiryDate > now.
  3. For each sub, calculates daysUntilExpiry.
  4. If daysUntilExpiry matches any of the reminderIntervals and no reminder has been sent today for that interval:
  5. Calls sendReminderEmail(sub, interval) (emailService.js).
  6. The service loads the default template of the matching type (e.g., reminder_30), replaces placeholders ({{domain}}, {{days}}, etc.), and sends via Nodemailer.
  7. Email log is recorded. The subscription’s remindersSent array is updated to prevent duplicates.

🤖 AI Template Generation

  1. User enters prompt (or picks from Ideas) → clicks “Create Email”.
  2. Frontend calls POST /api/templates/generate with { prompt }.
  3. Route calls generateTemplateFromPrompt(prompt) (aiTemplateService.js).
  4. The AI service sends a system prompt + user prompt to Gemini.
  5. Gemini returns a JSON object with name, subject, htmlBody, textBody, type.
  6. Backend validates the JSON and returns it to frontend.
  7. Frontend’s handleAITemplateGenerated pre‑fills the “New Template” form with the data.
  8. User reviews (can edit) and clicks “Create Template” → saved to database.
🧭 Complete User Guide (Step by Step)

1. Sign Up and Verify Your Email

Open the app, click “Register”. Fill in your name, email, and password. After submission, check your inbox (and spam) for a verification email. Click the link inside – you’ll be automatically logged in and redirected to the dashboard.

2. Set Up Your SMTP (Email Server)

Go to Email Settings in the sidebar. Enter your SMTP host (e.g., smtp.gmail.com), port (587 for Gmail), your email username, and the App Password (for Gmail). Fill in the sender email and name. Click Save Configuration, then Send Test Email to verify it works. If you’re using Gmail, follow the in‑page instructions to enable 2‑Step Verification and generate an App Password.

3. Add Your First Subscription

Navigate to Subscriptions and click Add Domain. In the form:

  • Enter the domain name (e.g., example.com).
  • Type the client’s name.
  • Add one or more client emails (click “+ Add Another Email” to add more).
  • Choose the Subscription Type (Domain, Hosting, etc.) and Renewal Cycle (Yearly, Monthly, etc.).
  • Pick the Expiry Date.
  • Select the reminder intervals by clicking the buttons (30d, 15d, 7d, 1d, etc.). At least one must be selected.
  • Add any notes if needed, then click Create.
The subscription will appear in the table with its status and days left.

4. Send a Test Reminder

In the subscriptions table, find the row of the domain you want to test. Click the paper plane icon (Send test email). A test email will be sent to the primary owner email using your saved SMTP settings. You’ll see a success or error toast.

5. Manage Email Templates

Go to Templates. You’ll see a list of existing templates. You can:

  • Seed Defaults – click this button to automatically create four pre‑designed templates (30‑day, 7‑day, 1‑day, expired).
  • Create a Template Manually – click “New Template”, fill in the name, type, subject, HTML body, and plain text body. Use the variable buttons ({{domain}}, {{owner}}, etc.) to insert placeholders.
  • Generate with AI – click the sparkle button, type a simple description (e.g., “Remind the customer 7 days before expiry with a friendly tone”), and hit “Create Email”. The AI will produce a complete template that opens in the creation form. Review it, make any changes, and save.
  • Use the 💡 Ideas button to pick a pre‑written prompt – click the sparkle on any card to send it directly to the AI.
Templates that are marked as “Default” will be used automatically by the cron job for matching reminder types.

6. Automatic Reminders

No manual action is needed. The cron job runs every day at 8:00 AM UTC and scans all active subscriptions. It sends reminder emails for any domain whose days‑until‑expiry matches one of its selected intervals. You can also trigger it manually from the Settings page (admin only) by clicking “Run Reminder Check Now”.

7. View Dashboard Insights

The Dashboard gives you a visual overview: total subscriptions, active/expiring soon/expired counts, a bar chart of upcoming expiries in the next 6 months, a donut chart of subscription types, a renewal cycle chart, and a list of recent subscriptions about to expire. Use this to plan your client communications.

❓ Frequently Asked Questions

Q: AI generation says “Failed to generate template”. What should I do?

Check the backend terminal for the actual error. Common reasons: expired or leaked Gemini API key, quota exceeded (free tier limits), or incorrect model name. Generate a new key in a new Google Cloud project, add it to .env, and restart the server. If you need an alternative, you can switch to OpenAI or Mistral by modifying aiTemplateService.js.

Q: Test emails from subscriptions work, but automatic (cron) reminders don’t arrive.

Check that the backend server is running at 8:00 AM UTC. If you’re using a free hosting service that sleeps, the cron job won’t trigger unless the server is awake. Use cron-job.org to call your manual cron endpoint (POST /api/settings/run-cron) at your desired time. Also verify that default templates exist – use “Seed Defaults” if not.

Q: How do I update the SMTP password?

If you’ve saved SMTP settings via the UI, simply edit them on the Email Settings page and click “Save Configuration”. If you’re using the .env fallback, update the SMTP_PASS variable in the .env file and restart the backend.

Q: Can I use a different email provider (not Gmail)?

Yes. Any SMTP server works. Just enter the correct host, port, and credentials in the Email Settings page. For example, SendGrid, Mailgun, or your own cPanel email.

Q: How do I add more reminder intervals (e.g., 60 days)?

Edit the COMMON_INTERVALS array in SubscriptionForm.jsx (frontend) and add the number. The backend already accepts any positive integer, so no other changes are needed.
